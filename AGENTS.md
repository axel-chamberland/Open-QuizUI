# AGENTS.md — Open QuizUI

Open WebUI tool/action function that renders interactive multiple-choice quizzes as embedded HTML.

## Commands

```bash
pip install -e .        # Python deps (no requirements.txt); use a venv
npm ci                  # JS dev deps
npm test                # Vitest (tests/*.test.js)
npm run test:python     # pytest (tests/test_*.py)
npm run test:all        # both
npm run build           # python backend/build.py — regenerates release/
npm run release         # test:all, then build (what CI/PR should end with)
```

## Build & release flow (important)

- `release/*.py` (action_function.py, tool.py) are **generated artifacts** — never edit them directly. Run `npm run build` after changes and commit the regenerated files.
- `backend/build.py` bundles `frontend/src/main.js` with esbuild, then merges base.css + HTML + bundled JS into the Python files. The output is a standalone single-file Open WebUI function.
- Anything in `backend/quiz_function.py` / `backend/quiz_tool.py` **after `def wrap_html(` is discarded by the build**; the Python source of truth is everything above that marker.
- `wrap_html()` is generated by build.py — changes to it in the backend files are overwritten. If its call signature changes (e.g. a new setting gets passed to the frontend), also update the emission template in `backend/build.py` (it hardcodes the parameter list).
- User-facing settings (valves) live in the `Valves(BaseModel)` class inside `backend/quiz_function.py` and `backend/quiz_tool.py` — those are above the build cutoff and preserved; edit them directly. Both copies have their own `Valves` class — keep them in sync when a setting applies to both.

## Architecture

- `backend/quiz_function.py` — action function (post-message button, parses free-form LLM quiz output; version `2.2.1` in module docstring, pyproject version lags).
- `backend/quiz_tool.py` — tool variant (structured tool-call input).
- Both duplicate shared logic (THEMES dict, parsing). Themes are Python-side; they are injected at runtime into the build template, so theme edits go in the `.py` files, not CSS.
- `frontend/src/` — vanilla ES-module JS (no framework, no bundler at dev time; esbuild only runs inside `backend/build.py`). `frontend/index.html` is the dev entry (`python -m http.server` on `frontend/` serves it — module imports require HTTP, not `file://`).

## Gotchas

- Python ≥ 3.12 (pyproject). CI uses Python 3.12 / Node 22; the docs claim 3.11 too — pyproject wins.
- Vitest files opt into jsdom per-file via `@vitest-environment jsdom` comment; frontend modules are mocked for unit tests.
- CI (`.github/workflows/tests.yml`) runs `npm run test:all` only — it never verifies the build is fresh, so a stale `release/` from source changes will pass CI unnoticed.
- repo remote is `Open-QuizUI` (git remote), while backend docstrings reference `OpenQuizUI` GitHub Pages — docs are in `docs/` with Development/Contributing/Formatting pages.
- This project doesn't vendor Open WebUI. To verify Open WebUI internals (Functions/Tools API, valves, event emitters) against the real project, consult upstream: the `open-webui/open-webui` repo and openwebui.com/docs. Any local reference checkout stays gitignored and uncommitted.
